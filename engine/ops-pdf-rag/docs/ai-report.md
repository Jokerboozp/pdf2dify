# ERP 运维知识库 —— AI 能力专题汇报

汇报人：（填写）　资料处理完成：2026-09-16　资料规模：257 份 PDF / 5,244 页
说明：每点分「开发成果」（技术上做出来了什么、有据可查）与「应用效果」（业务上带来什么变化）两段。

## 总述：这个项目的 AI 定位

这不是"用 AI 写了个脚本"，而是**自建了一套领域 RAG（检索增强生成）系统**，
把 670 MiB 只读手册变成可溯源问答能力。AI 用在四个位置：

| AI 环节 | 承担的工作 | 技术选型 |
|---|---|---|
| 多模态感知 | 把图片里的字认出来 | RapidOCR + ONNX Runtime + Pillow（本机） |
| 知识表示 | 把手册切成可检索、可回溯的语义单元 | 章节结构 + 父子分段 + 元数据 |
| 语义检索 | 找到答案依据 | 本地嵌入模型 + 混合检索（向量 0.7 / 关键词 0.3） |
| 证据约束生成 | 只依据检索结果作答，不确定就拒答 | DeepSeek + 提示词约束 + 结构化输出 + 追问分支 |

**一句话效果：** 问一句 → 返回**原文操作步骤 + PDF 页码 + 原页截图**，
资料没有依据时明确拒答，全部内容可回溯原始文件。

## 一、AI 多模态读取：让图片里的字变成可检索知识

**开发成果**
- 建成"原生文字 + 截图 OCR"双通道读取：pdfplumber 提正文，RapidOCR（ONNX Runtime 推理）+ Pillow 处理图像。
- 全量执行：5,244 页、5,006 张截图，产出原生文字 181.7 万字符 + OCR 文字 167.9 万字符、24.1 万行识别结果。
- 识别质量量化：**平均置信度 0.913，P90 = 0.999**；逐行输出置信度，低于阈值自动打标。
- 用图片哈希建立装饰图黑名单（logo、背景、页眉），拦掉无意义识别，减少噪声。

**应用效果**
- ERP 手册的关键信息大量在截图里（事务码、字段名、按钮名），纯文字提取会漏；
  OCR 通道把它补了回来，**5,006 张界面截图成为可被检索的知识**。
- 低置信行自动生成**待复核清单**（9,380 行，占 3.9%），人工只核对可疑部分，不必全量重看。
- 全程本机推理，**手册和截图不出内网**。

---

## 二、AI 知识表示：把 5,244 页切成"能检索、能回溯"的语义单元

**开发成果**
- 依据 PDF 书签、章节标题和坐标切分，不用固定长度硬切，**否定条件、表格、跨页步骤保持完整不截断**。
- 采用**父子分段**：以章节为父文档（4,840 条），子块 500 token、重叠 60；命中子块后返回完整父文档。
- 每条内容带元数据：来源文件 SHA256、页码、截图坐标、置信度。
- 为提升召回，从原文标题生成**检索锚点** 4,561 条（只用原文措辞，不让模型生成业务答案）。
- 溯源校验 5,244 页、8,084 处图片引用，**错误 0 项**。

**应用效果**
- 解决 RAG 最常见的"答案被切断"问题：跨页流程和"若…则…否则…"的条件分支能整段给出，不会只给半条。
- 命中后拿到的是完整章节 + 原图，用户看到的是**手册原貌**，不是模型的转述。

---

## 三、AI 检索：先找对依据，再谈回答

**开发成果**
- 部署本地嵌入模型 `nomic-embed-text`（Ollama），9 个主题库全部启用高质量索引。
- 采用**混合检索**：向量权重 0.7、关键词权重 0.3，Top K=5（全量库 6），权重可调。
- 分层检索策略：单库检索（9 个）+ **跨库组合检索**（项目管理/财务、设备/财务、采购/主数据、内部交易/资金、财务/资金共 5 组），
  共 14 条检索链路写进工作流。
- 建成本地 BM25 检索基线，用于排查"哪些业务问题还没被覆盖"。

**应用效果**
- 纯向量检索对 ERP **事务码、字段名、单据号**这类精确词容易飘；混合检索把关键词权重补上，
  实测离线评测：**Top1 命中 97.5%、Top5 命中 100%**（60 条用例中 40 条可评分）。
- "冲销结转"和"维修工单结算"是两个模块的相似流程，跨库检索能按对象区分，避免串到别的模块。

## 四、AI 生成：只依据证据回答，没依据就拒答

**开发成果**
- 回答链路：问题理解与指代补全 → 判断关键条件是否缺失 → 追问 / 检索 → 核对适用条件 → 作答并附页码。
- 用提示词约束生成范围：**禁止补写原文没有的操作**，禁止混入其他对象的处理方法。
- 引入**拒答与澄清分支**：资料无依据时明确说明；对象不明确时先追问，不猜。
- 结构化输出（JSON）替代代码节点，绕开服务器沙箱限制，保证流程稳定。
- 用真实失败样例迭代提示词并回归：修掉了"串答另一页故障处理方法""多轮追问返回占位符"两个缺陷。

**应用效果（实测记录）**
- 问"项目结转后怎么撤销"→ 返回原文三步：CJ88 → 变式/期间/年度与结转时保持一致 → "结算 → 冲销"，
  并注明**《财务模块常见问题》PDF 第 17 页**，该页原图可点击放大。
- 问"Linux 服务器查看磁盘使用率的命令"→ 回答**知识库依据不足**，没有拿通用知识补写命令。
- 问"资料是否适用于 S/4HANA 2023"→ 回答**无法确认**，没有冒充已验证版本。
- 问"怎么删除？"→ 先追问删除对象/单据，不直接给步骤。
- 6 次真实浏览器联调覆盖单轮、多轮追问、两种澄清、资料不足与另一业务流程，均正常返回。

**这是本项目和普通问答机器人的核心差别：可核对、会认错。**

## 五、AI 对话理解：多轮、指代、路由

**开发成果**
- 多轮指代补全：把"那 02 可以填上个月吗？"这类省略问句还原成完整检索问题。
- 意图与范围识别：判断问题属于哪个业务模块，只检索对应库或跨库组合；超出运维资料范围时说明边界。
- 关键条件抽取：识别对象（项目结转/维修工单）、动作、期间年度等条件，缺失就追问。

**应用效果**
- 用户不必背事务码、不必说全模块名，用日常说法就能问到原文；
- 实测多轮追问"那 02 可以填上个月吗？"能对上文的"冲销原因 02"作答并引用同一页码。
- 问"帮我预测明天的股票涨跌"会说明超出运维资料范围，不浪费检索也不乱答。

## 六、AI 质量保障：可评测、可回归、可持续调优

**开发成果**
- 建 60 条测试用例集（含 13 条 holdout 未用于调参），YAML 管理、脚本可复跑。
- 28 个自动化测试覆盖字段顺序、否定条件与数字保留、溯源、检索区别、续跑与工作流兼容性，**当前全部通过**。
- 输出指标：hit@1 / hit@5，并单独统计 dev 与 holdout，避免"用调参集自证"。
- 用文件哈希 + JSON 状态实现缓存与断点续跑，改配置/换文件可自动判断是否需重跑。

**应用效果**
- 改提示词、换分段、调权重后**能立刻量化是否变好**，不是凭感觉判断。
- 全库冷处理 1.36 小时（64 页/分钟）、失败 0 页；新增或改版手册走增量更新，不用重建工程。

## 七、AI 部署方式：本地推理 + 数据不出内网

**开发成果**
- OCR、图像处理、向量化全部本机执行；云端模型只接收**检索命中的文字摘要与图片链接**，不接收原始 PDF。
- 未启用云端视觉输入，模型不读取图片做云端 OCR。
- 图片由知识库自身存储，回答中的配图链接可直接在页面显示。
- 本地模型与远端模型解耦，后续可替换嵌入或生成模型而不动数据资产。

**应用效果**
- 满足内网资料合规要求：**原始手册不出本机**，只把必要片段送进生成环节。
- 数据资产（逐页 JSON、坐标、图片）留在本地，换模型不用重做资料处理。

## 九、边界与后续 AI 方向（主动说明）

**当前边界**
- 命中率是本地词法+检索基线，**不等于回答准确率**；端到端业务验收未完成。
- 9,380 行低置信 OCR 是**待复核标记**，不是 9,380 个错误。
- 手册的适用系统版本、岗位权限、业务时效未由业务负责人确认。
- 未配置重排模型，`reranking_enable = false`，检索参数（0.7/0.3、Top K）仍是试点起点。
- 云端模型不读图，图片仅作证据展示，不做图像理解。

**后续 AI 方向（按优先级）**
1. **接重排模型**：对 Top 20 候选重排，先解决"找得到但排得靠后"的漏召回。
2. **长流程方案**：跨多页带分支的流程改父子分段 + 结构化步骤抽取，单独建库验收。
3. **业务问题集驱动调参**：用真实高频问题替换开发用例，重调权重、Top K 与分段粒度。
4. **质量闭环**：把线上回答的点赞/纠错回流成评测用例，形成"用一次、准一点"的循环。
5. **元数据过滤**：按模块、系统版本、岗位过滤检索范围，减少版本误用。

**请求支持**：请各业务模块负责人抽 20~30 条高频问题做验收，确认适用版本与权限口径——
这是把"技术验证"变成"可上线"的必经一步。
