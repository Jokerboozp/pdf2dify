# 运维回答配图接入

原先只有文字，是因为 TXT 导出没有图片内容，也没有可供浏览器加载的图片地址。当前已在同一知识库导入图文版，包含 44 条完整问答、43 条带图问答和 77 张原文截图。纯文字 TXT 已禁用、保留回退，避免重复召回。没有原图的财务 FAQ 第24页仍为文字回答。

## 当前工作方式

1. 在本地从 PDF 中提取截图，按已确认的图片哈希排除装饰 logo 和背景。
2. 根据原 PDF 的 source_id 和页码把图片放回对应问答，保持页内从上到下的顺序。图中的红框、箭头在截图内保留。
3. 使用 DOCX 作为图文导入容器，一个问题及其图片放在同一个自定义分段内。每段少于 Dify 的10张附件上限，每张图片小于2 MiB。
4. Dify 把嵌入的图片保存为自身文件，并在分段正文中产生 `![image](/files/.../file-preview)`。无需把原始 PDF 交给云端 OCR，也无需本机长期提供 HTTP 图片服务。
5. 回答节点仅展示实际用于回答的同一条证据的图片，最多3张；无依据、需澄清或原文无图时不凑图。当前视觉输入关闭，云模型不读取图片内容。

实现依据：[Dify 本地文件导入文档](https://docs.dify.ai/en/cloud/use-dify/knowledge/create-knowledge/import-text-data/readme)和 [Dify 1.17.1 Word 提取器](https://github.com/langgenius/dify/blob/1.17.1/api/core/rag/extractor/word_extractor.py)。实际目标实例已验证 DOCX 图片可保留在对应知识分段。

## 后续重新生成

保持现有 `export/manifest.json` 作为选入卡片清单后执行：

```powershell
Set-Location D:\rag\ops-pdf-rag
.\scripts\build-image-bundle.ps1
```

脚本用现有卡片生成图片任务清单，调用本地 OCR 管线补齐尚未处理的页，再使用 Codex 的文档运行时生成图文包。重复处理会命中缓存。`-PlanOnly` 只生成任务清单。

导入新包完成索引后，停用被替代的旧版本；不要让多个版本同时启用。Dify 生成的文件ID每次导入可能变化，不能手工编造或硬编码旧链接。

这个 DOCX 是程序导入容器，不作为排版文档交付。本机没有 LibreOffice，`render_docx.py` 无法执行版面渲染；本次通过 OOXML 图片哈希校验、Dify 分段预览和实际聊天图片放大显示检查导入结果。
