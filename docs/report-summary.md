## 二、做了什么（技术方案）

一套本地运行的自动化产线，把只读 PDF 转成可问答的知识库，共 8 个环节：

1. 批量扫描与清点：pypdfium2 统计页数，SHA-256 建立文件指纹（资料一改就能发现）。
2. 原生文字提取：pdfplumber 逐页提取正文，按 JSON 结构化保存。
3. 截图文字识别：RapidOCR + ONNX Runtime + Pillow，识别扫描页和系统界面截图。
4. 内容整理：正则规则 + Markdown + python-docx，生成 FAQ 卡片与跨页流程文档。
5. 证据溯源：JSON 元数据记录来源文件、页码、截图坐标。
6. 本地检索：BM25 词法检索与关键词匹配。
7. 工程保障：文件哈希 + JSON 状态管理，实现缓存、断点续跑、增量更新。
8. 质量验证：pytest 测试 + YAML 用例 + 检索评测脚本。

> 技术栈：Python 3.12 + pypdfium2 / pdfplumber / RapidOCR(ONNX) / python-docx，
> 对接 Dify 1.17.1 + DeepSeek，全部本地部署，未调用云端 OCR。

## 四、效果（做了什么不一样的事）

**1. 答案直接给出处，可核对**
实测问"项目结转后怎么撤销？"，系统返回原文三步操作（事务码 CJ88 → 变式/期间/年度与结转时保持一致 →
左上角"结算 → 冲销"），并标注来源：**财务模块常见问题.pdf 第 17 页**，附该页原图可点击放大。
不是模型自己编的答案，是原文加页码。

**2. 问错了会拦住，不乱答**
资料里没有的内容不硬答：实测问"Linux 服务器查看磁盘使用率的命令"，系统明确回答**知识库依据不足**；
问料是否适用于 S/4HANA 2023，回答**无法确认适用版本**。
关键信息缺失时先追问（问"结转怎么撤销"会先澄清是项目结转还是维修工单）。

**3. 找资料从"翻手册"变成"问一句"**
原先要在 257 份手册里按目录逐页找操作步骤，现在一次检索直接定位到条目、页码和界面截图，
候选范围从 5,244 页收敛到 Top 5 条证据。

**4. 形成可复用产线，不是一次性项目**
15 个模块 + 14 个脚本构成固定流程（扫描→提取→识别→整理→入库→评测）。
后续新增或改版手册，按同一条命令**增量更新**，不用重建工程。

**5. 数据不出本地**
PDF 渲染、截图裁切、OCR 全部本机执行，云端模型只接收检索到的文字和图片链接。

## 五、需要说明的边界（主动讲，避免被追问）

- 上述命中率是**本地检索基线**，不等于线上回答准确率；答案正确率仍需业务侧验收。
- OCR 平均置信度 0.913，其中 9,380 行是低置信**待复核标记**——是待核对清单，不是 9,380 个错误。
- 手册的**适用系统版本、岗位权限、业务时效**尚未经业务负责人确认，系统遇到不确定会回答"无法确认"。
- Dify 端到端全量验收、长流程分段、重排模型和检索参数调优仍在进行。
